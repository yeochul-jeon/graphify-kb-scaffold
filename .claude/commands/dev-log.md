현재 작업 단계를 `logs/DEV_LOG_{yyyymmdd}.md`에 구조화된 형식으로 기록합니다. Triggers: dev-log, log step, record progress, 개발 로그, 작업 기록

## 사용법

```
/dev-log [단계명]
```

`$ARGUMENTS`가 있으면 해당 문자열을 단계명으로 사용합니다.
없으면 직전 작업 내용을 바탕으로 단계명을 자동 추론합니다.

## 처리 순서

### Step 1: 오늘 날짜의 DEV_LOG 파일 확인

- 파일명: `logs/DEV_LOG_{오늘날짜 yyyymmdd}.md` (예: `logs/DEV_LOG_20260406.md`)
- 파일이 없으면 아래 헤더로 신규 생성:
  ```markdown
  # DEV_LOG — YYYY-MM-DD

  작업 단계별 의사결정, 시도, 오류, 해결 과정을 기록합니다.

  ---

  <!-- 아래부터 새 단계 추가 -->
  ```
- 파일이 있으면 읽어서 기존 항목과 중복 여부를 확인합니다.

### Step 2: 직전 작업 컨텍스트 수집

현재 대화에서 방금 완료한 작업을 기준으로 다음을 추출합니다:

- **결정**: 어떤 방식을 선택했고, 왜 그 방식인가 (대안 대비 이유 포함)
- **시도**: 실제로 취한 접근법 및 사용한 도구/커맨드
- **오류**: 발생한 에러나 예상과 달랐던 점 (없으면 "없음")
- **해결**: 오류/문제를 어떻게 해결했는지 (없으면 "-")
- **메모**: 다음 단계에서 참고할 사항, 주의점, 잔여 과제

### Step 3: logs/DEV_LOG_{yyyymmdd}.md 항목 추가

`logs/DEV_LOG_{yyyymmdd}.md` 하단(`<!-- 아래부터 새 단계 추가 -->` 주석 아래)에 다음 형식으로 append:

```markdown
## [단계명] — YYYY-MM-DD

- **결정**: [선택한 방식과 이유]
- **시도**: [사용한 방법/도구/커맨드]
- **오류**: [에러 내용 또는 "없음"]
- **해결**: [해결 방법 또는 "-"]
- **메모**: [다음 단계 참고사항]

---
```

### Step 4: log.md에도 기록

`log.md` (프로젝트 루트) 파일 끝에 다음 형식으로 append:

```
## [YYYY-MM-DD] decision | [단계명]
- detail: [핵심 결정 내용 한 줄 요약]
```

### Step 5: 완료 보고

추가된 항목의 단계명과 위치를 한 줄로 보고합니다.

## 규칙

- 한 번 호출 = 한 항목 추가 (여러 단계를 묶지 않음)
- 오류가 없었더라도 항목을 생략하지 않음
- 작업 결과물 파일 경로는 **시도** 또는 **메모**에 포함
- 길이: 항목당 5줄 고정 (형식 엄수)
