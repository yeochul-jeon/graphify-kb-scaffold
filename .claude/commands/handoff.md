현재 세션을 다음 세션이 이어받을 수 있는 핸드오프 문서로 `.claude/reports/handoff/<YYYY-MM-DD>.md`에 기록합니다. 완료 작업·주요 결정·피해야 할 함정·관련 파일(줄 번호 포함)·남은 작업 상태·새 대화용 프롬프트를 담습니다. Triggers: handoff, 핸드오프, 인계, 세션 정리, 다음 세션, hand off, session summary, 마무리

## 사용법

```
/handoff              # 오늘 날짜로 작성
/handoff [부제]       # 부제를 지정
```

세션을 끝낼 때 다음 세션이 **문맥 없이 이어받을 수 있는** 문서를 만든다. 회고가 아니라 인계다.

## 산출 경로

`.claude/reports/handoff/<YYYY-MM-DD>.md`

같은 날짜 파일이 이미 있으면 **덮어쓰지 않는다.** 기존 파일을 읽고 이번 세션 분을 별도 절로 덧붙이거나, 사용자에게 파일명 접미사를 묻는다.

> 이 저장소의 기존 핸드오프는 `YYYY-MM-DD-NNN-슬러그.md`(일련번호 포함) 형식도 함께 쓴다. 연속성이 중요한 회차 작업이면 그 형식을 따르고, 단발 세션이면 날짜만 쓴다.

## 작성 원칙

1. **검증 가능한 것만 적는다.** 파일 경로에는 줄 번호를, 수치에는 측정일과 측정 방법을 붙인다. 확인하지 않은 것은 "미확인"으로 적는다.
2. **미실행을 0으로 적지 않는다.** 재지 않은 항목은 "미측정"이다.
3. **Open Work는 상태 서술형으로 쓴다.** *"X를 하라"*가 아니라 *"X는 미적용 상태다"*. 명령형은 다음 세션의 판단을 미리 잠근다.
4. **자기 오류를 숨기지 않는다.** 세션 중에 뒤집힌 주장은 함정 절에 남긴다 — 그것이 이 문서에서 가장 값나가는 부분이다.
5. **길이보다 밀도.** 다음 세션이 같은 조사를 반복하지 않게 하는 문장만 남긴다.

## 문서 구조

### 머리말

세션 성격 한 줄, 측정 기준일, 커밋 상태(커밋됨/미커밋).

### 1. 완료된 작업

산출물을 표로 — 무엇을, 어디에. **완료하지 않은 것을 완료로 적지 않는다.** 의도적으로 하지 않은 일이 있으면 그 사실과 이유를 여기에 적는다.

세션 중 수행한 측정이 있으면 **재실행 시 같은 값이 나와야 하는 형태로** 기록한다(명령어 + 결과 + 측정일).

### 2. 주요 결정

`D1`, `D2` … 로 번호를 붙인다. 각 항목에 **왜 그렇게 정했는지**를 한 줄 이상 적는다. 근거 없는 결정은 다음 세션이 되돌린다.

기각·폐기한 안도 결정이다. 무엇을 왜 버렸는지 적는다.

### 3. 피해야 할 함정

**이 세션이 실제로 밟았거나 밟을 뻔한 것만.** 일반론을 적지 않는다.

`T1`, `T2` … 로 번호를 붙이고, 각 항목에 ① 틀린 서술 ② 실제 값 ③ 왜 틀렸는지(측정 정의의 어느 부분이 어긋났는지)를 적는다.

우선순위 표시: 🔴 결론을 바꾼 오류 / ⚠️ 서술을 약화시킨 오류.

### 4. 관련 파일

세 갈래로 나눈다.

- **이번 세션이 만든 것** — 경로 + 내용 한 줄
- **조치 대상 / 수정이 필요한 것** — `경로:줄` + 어긋난 내용 + 대조 대상. 줄 번호 없이 적지 않는다
- **근거·규율 문서** — 읽어야 판단이 서는 파일 + 왜 필요한지

### 5. 남은 작업 상태

**상태 서술형으로만 쓴다.** 각 항목에 지금 어떤 상태인지, 무엇이 정해지지 않았는지를 적는다.

- ❌ "조치 8건을 적용하라"
- ✅ "조치 8건은 미적용 상태다. 적용 시점이 정해지지 않았다"

포함할 것: 미결 판단, 사람 답변 대기 항목, 커밋 상태, 파생 산출물(그래프·색인 등) 재빌드 필요 여부와 그 근거.

### 6. Prompt for New Chat

새 대화에 그대로 붙여넣을 수 있는 블록. 코드 펜스로 감싼다.

포함할 것:
- 먼저 읽을 파일 목록 (핸드오프 자신 포함)
- 현재 상태 요약 3~5줄
- 지켜야 할 제약 — 이번 세션이 스스로 건 것 포함
- 특히 위험한 함정 1~2개를 실명으로

**마지막 줄은 반드시 다음 문장으로 끝낸다:**

```
나열된 파일을 실제로 Read 도구로 읽고 이 문서의 주장을 코드와 대조해 검증해.
```

## 처리 순서

### Step 1: 세션 이력 정리

무엇을 만들었고, 무엇을 측정했고, 무엇이 뒤집혔는지 되짚는다.

### Step 2: 줄 번호 재확인

주장할 파일·줄 번호를 **실제로 확인한다.** 기억으로 줄 번호를 적지 않는다 — `grep -n`으로 다시 잡는다.

### Step 3: 수치 재확인

인용한 수치를 다시 잰다. 같은 값이 두 파일에서 갈리면 **어느 파일에서 읽었는지 명시한다.**

### Step 4: 작성

위 §문서 구조 6절 순서로 쓴다.

### Step 5: 보고

저장 후 **경로와 §6 프롬프트 블록만** 사용자에게 보고한다. 문서 전문을 다시 출력하지 않는다.

## 하지 않는 것

- 커밋하지 않는다 — 사용자가 요청할 때만.
- `.claude/reports/handoff/_current.md` 같은 누적 상태 문서를 자동으로 고치지 않는다. 갱신이 필요하면 §5에 "미갱신 상태"로 적고 사용자 판단에 맡긴다.
- 다음 세션의 작업을 지시하지 않는다. 상태만 넘긴다.
- `log.md`에 항목을 추가하지 않는다 — 그것은 `/dev-log` 담당이다.
