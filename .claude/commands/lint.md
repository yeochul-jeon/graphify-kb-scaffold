wiki 품질 자가 점검. 깨진 링크, 고아 파일, 중복, 오래된 콘텐츠 등을 탐지합니다. Triggers: lint, check quality, validate wiki, broken links, orphan files, 점검, 검증

## 사용법

```
/lint              # 문제 탐지 후 보고서만 출력 (단, 탐구 제안 파일은 항상 갱신)
/lint --fix        # 탐지 후 자동 수정 가능한 항목 처리
/lint --quick      # 구조적 점검만 (#1~#8) — 의미론적 분석 생략
/lint --quick --fix  # 구조적 점검 + 자동 수정
```

### 재측정 규율 — 이월 항목을 다룰 때 (2026-07-27 확정)

원장(`_meta/weather.md`·`_current.md`)에 **"N회 연속 이월"** 로 남아 있는 항목을 만나면 순서가 정해져 있다.

1. **고치기 전에 먼저 잰다.** 이월 횟수는 심각도가 아니라 **재검증 신호**다. 2026-07-27 에 3건을 재측정했더니 전부 판정 오류였다 — 미조치가 아니라 오보였다.
2. **재측정은 그 수치를 만든 검사기의 정의로 한다.** 임의 임계값으로 재면 **정정이 새 오류가 된다.** AI/LLM 하네스 항목을 30일(점검 #3 기준)로 재서 90일 기준(점검 #12) 원장을 "틀렸다" 고 오판한 것이 실제 사례다. 90일로 재면 원장이 정확히 맞았다.
3. **수치가 다르다고 곧바로 틀린 것이 아니다.** 도구마다 정의가 다르면 여러 값이 동시에 옳을 수 있다. 위 세 도구 15·16·19 가 그랬다.
4. **탐지 결과를 결함으로 올리기 전에 매칭 위치를 확인한다.** 문서 본문의 코드블록·예시가 frontmatter 로 오인되기 쉽다 — `markdown-wiki.md` 가 `created: YYYY-MM-DD` 미치환으로 보고됐으나 실제 frontmatter 는 `2026-04-06` 이었고, 매칭된 것은 형식을 설명하는 ```yaml 예시였다(2026-07-27 오탐).

> 이 규율은 `/lint` 밖에서도 적용된다 — 핸드오프·원장의 이월 항목을 다루는 모든 작업이 대상이다.

  - ⚠️ **신규 파일은 「부착 후 카운트」로 잰다** (원장 #32-(a)). 신규 개념이 **기존 태그를 2회 → 3회로 밀어 올리는 경로**가 실재하며, 신규 태그만 세면 그 경로를 놓친다.
- **중복 행 검사** (2026-08-07 신설, 원장 #26 조치안 ②): 같은 태그가 **행 두 개 이상**을 갖는지 탐지해 WARN. 커버리지 검사는 *"행이 **없는** 태그"* 만 보므로 **행이 둘이면 통과한다** — 18회차에 중복 5종(`#kiro`·`#mcp`·`#multi-agent`·`#plugin`·`#vibe-coding`)이 그렇게 빠져나갔고, 한 행만 본 독자는 나머지 개념을 놓친다. **커버리지와 달리 완전 기계 판정이 가능하다.**

### 8. 미검증 파일 점검

> ⚠️ **`verified: false` 전건을 나열하지 말 것** (2026-07-27 재정의). **거의 전부**가 `false` 라 목록이 곧 전체 파일이고, 그래서 이 점검은 여러 회차 동안 행동으로 이어진 적이 없다. 세 필드의 역할 분리는 `.claude/rules/wiki-concepts.md` §검증 3필드의 역할 분리 가 단일 출처다 — **`verified: false` + `last_verified: 날짜` 는 모순이 아니므로 결함으로 집계하지 말 것.**

점검 대상은 아래 셋이다.

- **(a) 사람 승인 대기 큐** — `last_verified` 에 날짜가 있는데 `verified: false` 인 파일. 에이전트가 출처 대조를 마쳤고 사람 승인만 남은 상태라 **바로 조치 가능한 목록**이다.
- **(b) 금지 조합** — `verified: true` 인데 `last_verified: null`. 대조 없이 승인했다는 뜻이라 성립하지 않는다. 발견 시 결함으로 보고한다.
- **(c) 재점검 만료** — `review_due` 가 오늘보다 이전인 파일. `verified` 값과 무관하게 잡는다(에이전트 대조분도 만료된다).

> **(c) 를 뺀 채 (a) 만 운영하지 말 것.** `review_due` 는 2026-07-27 까지 **아무 검사도 읽지 않는 필드**였다 — 값은 적히는데 만료돼도 아무 일이 없었다. `verified` 가 거의 전부 `false` 로 죽은 것과 같은 구조(필드는 있고 절차가 없음)이며, 승인 절차만 만들고 만료를 빼면 **두 번째 죽은 필드를 만든다.**

```bash
# (a) 승인 대기 큐 / (b) 금지 조합 / (c) 재점검 만료
# 주의: [[ ]] 필수. [ "$d" \< "$TODAY" ] 는 zsh 에서 "condition expected: <" 로 깨진다.
#       ISO 날짜라 문자열 비교가 곧 날짜 비교다.
TODAY=$(date '+%Y-%m-%d')
# 값 추출은 키 뒤 공백 수와 무관해야 한다. `sed 's/key: //'` 는 `: ` 두 글자가 없으면
# 치환하지 않아 값 없는 키에서 **키 문자열 자체**를 값으로 돌려준다 (원장 #36).
fmval() { sed -n "s/^$2:[[:space:]]*//p" "$1" | head -1; }
# "값 없음" 은 null 하나가 아니다 — 빈 문자열·''·"" 를 모두 포함해야 한다.
isnull() { case "$1" in ''|null|"''"|'""') return 0 ;; *) return 1 ;; esac; }
for f in wiki/concepts/*.md wiki/topics/*.md; do
  v=$(fmval "$f" verified); l=$(fmval "$f" last_verified); d=$(fmval "$f" review_due)
  [[ "$v" == "false" ]] && ! isnull "$l" && echo "(a) 승인대기: $f"
  [[ "$v" == "true"  ]] &&   isnull "$l" && echo "(b) 결함: $f"
  ! isnull "$d" && [[ "$d" < "$TODAY" ]] && echo "(c) 만료($d): $f"
done
```

**(a) 를 조치하는 절차** — 승인 체크리스트와 기록 방법은 `.claude/rules/wiki-concepts.md` §사람 승인 절차 가 단일 출처다. `--fix` 로 자동화하지 않는다(사람 승인이 정의상 사람의 행위다).

> 🔴 **(a) 가 0 이면 「승인할 것이 없다」가 아니라 「입력이 끊겼다」일 수 있다** (2026-08-10, 원장 #59). 이 큐는 **누군가 대조 후 `last_verified` 를 적어야만** 채워진다 — 그 기재가 절차에 없던 19회차 동안 구조적으로 0이었다. **대조를 수행했다면 그 자리에서 `last_verified` 를 남긴다**(`wiki-concepts.md` §대조를 마치면 그 자리에서 `last_verified` 를 남긴다). ⚠️ **검사기로는 못 잡는다** — 기록하지 않은 대조는 흔적이 없어 *"대조를 안 한 것"* 과 구별되지 않는다.

- **`--fix` 불가**: (a)는 사람이 본문을 읽고 `verified: true` 로 바꿔야 한다. (b)는 어느 쪽이 맞는지 사람이 판단해야 한다.

#### 11-1. 이 파일은 원장(ledger)이다 — 전체 재생성 금지

⚠️ `suggested-investigations.md` 는 **회차마다 덧붙는 누적 문서**다. 실행마다 새로 만드는 보고서가 아니다. 회차를 거치며 쌓인 종결 이력과 보관본이 이 파일의 주된 가치다.

| 회차마다 **갱신**되는 것 | 회차를 넘어 **보존**되는 것 |
|---|---|
| 상단 `> 마지막 업데이트:` 행 | 기존 항목 전체 — **종결된 항목도 지우지 않는다** |
| 새 회차 요약 블록 **1개 추가** | 이전 회차 요약 블록 **전부** |
| 신규 제안 항목 **추가** | `<details>` 보관 블록 **전부** |
| 기존 항목에 종결 표기 **부착** (§11-2) | 항목 번호 — **재사용·소급 개번 금지** |

**금지 사항 4가지**: ① 파일 전체 재생성 ② 종결 항목 삭제 ③ `<details>` 보관 블록 삭제 ④ 항목 번호 재사용·소급 개번.

**항목 번호 발급**: 신규 항목은 **`<details>` 보관본까지 포함한 전역 최대 번호 + 1** 을 받는다. 활성 항목만 보고 매기면 종결·보관된 번호를 다시 발급하게 된다.

> **왜 명시하는가**: 이런 원장은 규정이 "덮어쓰기" 로 적혀 있어도 실무에서는 자연스럽게 누적되는 쪽으로 굳는다. 규정과 관행이 갈라진 채로 두면, **규정을 문자 그대로 수행하는 실행자(사람이든 에이전트든)가 누적된 종결 이력과 보관본을 한 번에 소실시킨다.** 관행이 규정보다 옳을 때는 규정을 관행에 맞춰 고치는 것이 맞다.

#### 11-2. 종결 표기 관습

항목이 종결되면 **삭제하지 않고 종결 표기를 부착**한다. 4가지 관습을 지킨다.

**(a) 헤딩에 취소선 + 종결일 + 사유**

```markdown
### 12. ~~`null` 값이 검사를 우회한다~~ — **YYYY-MM-DD 조치 완료 (3회 이월 후)**
```

취소선(`~~제목~~`)이 **종결 여부의 단일 표식**이다. 본문의 `- **종결**:` 키와 반드시 짝을 이룬다 (§11-3).

**(b) 원 제안은 `<details>` 로 보관 — 삭제 금지**

종결 항목의 본문을 종결 서술(무엇을 했는지·무엇이 반증됐는지)로 바꾸면 **원래 제안 문구가 사라진다.** 원문은 접어서 남긴다.

**보관 블록이 필요한 조건**: 종결하면서 **원 제안의 `- **근거**:` 를 본문에서 걷어낸다면** 보관 블록을 만들어야 한다. 원 제안 필드를 제자리에 그대로 두고 종결 서술만 덧붙이는 경우에는 필요 없다.

> ⚠️ **판정 기준은 "취소선이 붙었는가" 가 아니라 "원 제안 텍스트가 아직 파일 안에 있는가" 다.** 취소선과 `- **종결**:` 키가 짝을 이뤄도 원문이 통째로 사라진 상태는 성립하며, 그것이 §11-1 이 막으려는 손실과 같은 종류다.

```markdown
<details><summary>원 제안 (N회차)</summary>

### 12. `null` 값이 검사를 우회한다 *(N회차 신규)*
- **근거**: ...

</details>
```

- **보관 블록 안의 `### ` 헤딩은 항목이 아니다.** 항목 수와 번호 중복을 셀 때 `<details>` 안쪽은 제외한다
- **단, 번호 재사용 검사는 예외다.** 안쪽을 그냥 빼면 보관된 옛 번호를 새 제안에 다시 발급해도 검사가 통과한다. 규칙은 이렇다 — **보관본의 번호는 그 보관본을 품고 있는 항목의 번호와 같아야 한다.** 다르면 번호 재사용이다
- ⚠️ **`<details>` 소속 판정은 줄 번호 depth 누적으로 한다.** 정규식으로 `<details>...</details>` 를 통째로 지우는 방식은 실제로 **존재하지 않는 번호 중복을 보고하는 오탐**을 낸다. 여는 태그와 닫는 태그를 줄 단위로 세어 depth 를 누적하라
- ⚠️ **depth 를 세기 전에 코드 스팬·펜스를 덮어라** (2026-08-07 신설, 원장 #41). 원장 규약은 링크·태그 문법을 백틱으로 감싸라고 요구하므로, 벗기지 않으면 **산문에 인용한 `<details>` 가 실제 태그로 집계돼** depth 가 열린 채 남는다 — 실측으로 **팬텀 번호 불일치 15건 + `--check` exit 1** 이 났다. 세 가지를 함께 지켜야 한다:
  - **펜스는 줄머리(들여쓰기 3칸 이내)에서만 토글한다.** 산문 중간의 ` ```yaml ` 은 펜스가 아니다 — 마크다운 문법이 그렇고, 이를 무시하면 짝이 안 맞는 순간 **문서의 큰 구간이 통째로 사라진다**(원장 실측: `_meta/*` 2파일이 이미 그 조건)
  - **인라인 스팬은 백틱 런을 맞춰 잡는다** — `` `x` `` 와 `` ``x`` `` 를 함께 처리해야 한다. 백틱 1개만 가정하면 이중 백틱 인용이 새어나간다
  - **마스킹은 줄 수와 개행을 보존한다.** 통째 치환(`sub(" ", text)`)하면 펜스 블록이 줄을 삼켜 **보고하는 줄 번호가 전부 어긋난다**
  - ✅ **직접 구현하지 말고 `scripts/wiki_scan.py` 를 `import` 한다** (2026-08-07 신설, 원장 #43). 위 세 규칙이 거기 구현돼 있고 `rebuild-backlinks.py`·`rebuild-cross-edges.py`·`lint-registry.py` 가 모두 그것을 쓴다. **직전까지 같은 정규식이 세 곳에 복제돼 있었고 그중 둘이 `re.S` 판이라 펜스 짝이 안 맞는 문서에서 본문을 삼켰다** — 실제로 링크가 사라지고 예시 링크가 남는 역전이 확인됐다([[suggested-investigations#43]])

**(c) 상단 회차 요약은 역순 누적**

`> **N회차 한눈에**:` 블록을 **최신이 위로** 오게 추가한다. 이전 회차 블록은 지우지 않는다.

**(d) 승계는 새 번호가 아니라 접미사**

한 항목이 후속 항목으로 이어질 때는 원 번호에 알파벳을 붙인다 — `### 33-b.`. 새 번호를 발급하면 원 항목과의 연결이 끊긴다.

> 번호 없이 알파벳만 쓰는 항목(`### A.`·`### B.`)은 **미분류 제안**이다. 정식 번호를 받기 전 단계이며, 승격 시 번호를 발급한다.

#### 11-3. 항목 형식 (최소 스키마)

```markdown
### 1. [제안 제목]
- **근거**: [이 제안이 나온 이유 — 어떤 갭이 발견되었는지]
- **관련 개념**: [[concept-a]], [[concept-b]]
- **유형**: 미연결 영역 | 얕은 커버리지 | 태그 갭 | 관련 외부 주제 | 프로세스 결함 | 누락 개념 | 측정 규율 | 메타데이터 커버리지 | 오래된 커버리지
- **종결**: resolved | refuted
```

> ⚠️ **위 `- **유형**:` 행은 산문이 아니라 기계 규격이다.** `scripts/lint-registry.py`
> `load_enum_set()` 이 이 행을 파싱해 M7 판정 집합을 만든다 — **하드코딩 기본값이 없어
> 파싱 실패는 곧 fail-closed** 다. 지시문을 "정리" 하는 작업이 이 행을 건드리면 검사기가 죽는다.
>
> 파손본 실측 (2026-08-10 · 무수정 기준선은 `--check` exit 0):
>
> | 조작 | 결과 |
> |---|---|
> | 열거 행을 표 형식으로 치환 | `exit 1` — *"`유형` 열거값 행을 찾지 못했다"* |
> | 열거 행 삭제 | `exit 1` — 동일 |
> | 실사용 확장 5종을 원래 4종으로 축약 | `exit 1` — **M7 위반 31건** |
>
> 형식(`- **유형**: A | B | ...`)과 값 집합이 **둘 다 계약**이다. 이 행은 열거값을
> **늘릴 때만** 고친다. §11-3 말미의 소급 변경 금지 조항과 짝이다.

**`유형` (분류 축)**

- 위 열거값 중 하나로 시작한다. 뒤에 괄호·`—` 로 세부를 덧붙일 수 있다 (`프로세스 결함 (검사기 정의 공백)`)
- **기저 유형** = 첫 구분자(`—` em dash · `/` · `(` · `→`) 이전 부분. 열거값 정합은 이 기저 유형으로 판정한다
  - ⚠️ **`→` 를 구분자 집합에서 빼면 안 된다.** 실사용에 `오래된 커버리지 → \`/ingest\`+\`/compile\` 재실행` 형태가 있고, `→` 가 없으면 그 뒤 코드 경로의 `/` 를 첫 구분자로 잡아 기저 유형이 깨진 문자열이 된다
  - 복수 유형(`A / B`)은 **첫 세그먼트만** 판정 대상이다
- ⚠️ **`유형` 에 종결 상태를 쓰지 않는다.** `— 해소`·`— 종결`·`— 이월` 같은 표기는 분류 축이 아니라 종결 축이며, 한 필드에 두 축을 접으면 **어느 쪽으로도 기계 판정이 안 된다.** 종결 축은 `- **종결**:` 키가 담당한다

**`종결` (종결 축)** — 값은 2개뿐이다.

| 값 | 조건 |
|---|---|
| `resolved` | 제안이 옳았고 조치가 완료됐다 |
| `refuted` | **전제가 틀렸다.** 재제안 금지 마킹 |

- **미종결 항목에는 이 키를 달지 않는다** — 부재가 곧 "진행 중" 이다
- ⚠️ **이월 횟수는 종결 사유가 아니다.** "N회 연속 미조치" 는 종결 조건이 아니라 **재검증 신호**다. 오래 남았다는 이유로 종결하면, 실제로는 전제가 틀렸을 뿐인 항목이 `resolved` 로 굳는다. 종결하려면 조치를 했거나 전제가 틀렸음을 확인해야 한다
- 값 뒤에 종결일·회차를 파이프로 덧붙일 수 있다: `- **종결**: refuted | YYYY-MM-DD | N회차`
- **취소선 ↔ `종결` 키는 항상 짝**이다. 한쪽만 있으면 결함이다

> **소급 변경 없음**: 열거값 확장(`프로세스 결함` 이하 5종)은 실사용을 규정이 따라간 것이다. **기존 항목의 `유형` 문구를 소급해 고치지 않는다.**

`--quick`에서는 구조 점검 기반 항목만 채우고 의미론적 항목은 "skipped by --quick"로 표시한다.

Required file shape:

```markdown
# Knowledge Weather

> Last updated: YYYY-MM-DD
> Generated by `/lint`; edit the source wiki pages, not this file.

## Storm
- Contradictions or severe broken-link issues.

## Fog
- Low confidence, missing sources, optional claim/evidence gaps.

## Stale
- Fast-moving AI/LLM/agent pages older than 90 days.

## Islands
- Orphan pages and graph/source-file isolation signals.
```

### 16. Source Ledger 점검

- **2026-08-12 (세션 35차) — generator 구현됨.** `python3 scripts/generate-source-ledger.py`(또는 `--check`)가 `wiki/_meta/source-ledger.md` 를 `raw/**/*.md` 전건 + `wiki/concepts`·`wiki/topics` 의 `sources` 역참조로 생성한다. **손으로 편집하지 않는다** — 재실행하면 덮어쓴다.
- `sources:` 는 인라인 `[...]` 과 YAML 블록 리스트 두 표기를 모두 파싱한다(파싱 안 하면 블록 표기 파일이 "출처 없음"으로 오판된다 — `wiki-concepts.md` 경고).
- `--check` 는 낡았으면 exit 1. `graphify-build.sh` 에는 아직 넣지 않았다(초안 단계 — 매 빌드마다 340+행을 갱신하는 비용 대 이득을 다음 회차가 판단).
- `wiki/concepts/` 및 `wiki/topics/` 아래 모든 `.md` 파일에서 frontmatter `sources` 필드 누락을 보고하는 것은 별도(기존 점검 #5 가 담당, 중복 구현 안 함).
- section-level source list는 권장 정책이며 기존 파일의 즉시 마이그레이션을 강제하지 않는다.

Generated Source Ledger shape (실제 컬럼 — `scripts/generate-source-ledger.py` 정본):

```markdown
# Source Ledger

| source | kind | compiled | wiki pages | trust | notes |
|---|---|---:|---|---|---|
| raw/example.md | raw | true | wiki/concepts/example.md | secondary | verbatim: true |
```

- `trust` = 그 출처를 인용하는 wiki 페이지들의 `evidence_level` 집합(다르면 `/` 로 병기, 인용 0건이면 `unused`).
- `notes` = `verbatim` 필드 상태 + 미인용 여부.

## 보고서 형식

`output/lint-report-YYYYMMDD.md`에 저장:

```markdown
# Lint 보고서 — YYYY-MM-DD

## 요약
| 항목 | 발견 수 | 자동수정 |
|------|---------|---------|
| 깨진 링크 | N | - |
| 고아 파일 | N | N (--fix) |
| 오래된 콘텐츠 (30일+) | N | - |
| 중복 개념 | N | - |
| 출처 누락 | N | - |
| index.md 미동기화 | N | N (--fix) |
| 태그 프리페이스 불일치 | N | - (수동 판단 필요) |
| backlinks.md 오류 | N | N (--fix) |
| 미검증 파일 | N | - (수동 검토 필요) |
| 누락 개념 페이지 | N | - |
| 모순 감지 | N | - |
| 탐구 제안 | N | (suggested-investigations.md 갱신) |
| 소스 갱신 권고 (AI/LLM) | N | - |
| 프론트매터 필드 누락 | N | - |
| Source Ledger 상태 | N | - |

## 상세

### 깨진 링크
- `wiki/concepts/foo.md`: `[[bar]]` → bar.md 없음

### 고아 파일
...

### 누락 개념 페이지
- `concept-name` (제안: `concepts/concept-name.md`): 3회 언급 (파일A, 파일B, 파일C) — 독립 페이지 권장

### 모순 감지
- `concepts/file-a.md` vs `concepts/file-b.md`: "6가지 패턴" vs "5가지 패턴" (숫자 불일치)

### 탐구 제안
- 3~5개 주제 → `wiki/_meta/suggested-investigations.md` 참조

### 소스 갱신 권고 (AI/LLM)
- `concepts/llm-compiler.md`: 업데이트 92일 전, 태그 [llm] — 최신 자료로 `/ingest` + `/compile` 재실행 권장

### 프론트매터 필드 누락
- `concepts/example.md`: 누락 필드 — `confidence`, `verified`

### Source Ledger
- `wiki/_meta/source-ledger.md`: 없음
- `concepts/example.md`: `sources` 필드 누락
```

