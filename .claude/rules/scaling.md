# 스케일링 가이드

## 현재 전략 (소규모: ~100 아티클)

- `wiki/index.md`를 항상 먼저 읽어 관련 개념 파악
- 관련 wiki 파일만 선택적으로 읽기 (전체 스캔 금지)
- Grep으로 키워드 검색 후 좁혀가기

## 중규모 (~100~500 아티클)

컨텍스트 제한 도달 시 적용:

1. **index.md 기반 필터링 강화**: 태그로 후보 좁히기 → 최대 10개 파일만 읽기
2. **topics/ 우선 탐색**: concepts/를 직접 읽기 전 topics/ 파일로 범위 파악
3. **Grep 적극 활용**: `Grep(pattern, path="wiki/")` 키워드 사전 필터링

## 대규모 (~500+ 아티클)

벡터 DB 없이 한계에 도달하는 시점. 대응 방안:

- wiki/ 전체를 읽지 않고 **index.md + backlinks.md + Grep** 3단계만으로 답변 시도
- 답변 품질이 낮다고 판단되면 "관련 wiki 파일 수가 많아 일부만 참조했습니다" 명시
- 이 시점에서 `/synthesize` (합성 데이터 생성) 도입 권장

## 핵심 원칙

- **읽기 순서**: index.md → topics/ → 해당 concepts/ (never 전체 wiki/)
- **컨텍스트 절약**: 답변에 불필요한 파일은 읽지 않는다
- **명시**: 컨텍스트 제한으로 일부 wiki 파일을 읽지 못했다면 사용자에게 고지
