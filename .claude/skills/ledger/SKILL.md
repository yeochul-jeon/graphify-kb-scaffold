# /ledger — 적용 원장

원장 파일은 `output/apply-ledger.md` 하나다. 파일이 없으면 «원장 없음: output/apply-ledger.md» 라고 보고하고, 빈 원장을 만들지 사용자에게 묻는다. 승인하면 아래 «빈 원장» 형식으로 만든다.

## 빈 원장

```markdown
# 적용 원장

> 나중에 적용할 항목을 한 곳에서 본다. 부르는 말: /ledger · «적용 원장 열어 줘» · «적용 원장에 추가해 줘»
> 규칙: 한 행 = 항목 · 상태 · 다음 행동 1줄 · 원천. 자세한 내용은 원천 답변에 두고 여기에는 쓰지 않는다. 끝난 행은 «끝난 항목» 절로 옮긴다.
> 상태 값: 미적용 · 진행 중 · 대기(사용자 결정) · 조건부(해당 작업이 생길 때)
> 갱신: YYYY-MM-DD HH:MM

## 진행 중인 항목

| # | 항목 | 상태 | 다음 행동 | 원천 |
|---|---|---|---|---|

## 끝난 항목

| # | 항목 | 끝난 날 | 원천 |
|---|---|---|---|
```

## 사용법

```
/ledger              # 진행 중인 항목 보기
/ledger add <항목>   # 행 하나 추가
/ledger done <#>     # 행을 «끝난 항목» 절로 옮기기
```

## 보기 (인자 없음)

1. `output/apply-ledger.md` 를 읽는다.
2. «진행 중인 항목» 표를 그대로 보여 준다. 상태별 행 수를 한 줄로 붙인다.
3. 원천 답변은 사용자가 행 번호를 지목할 때만 연다.

## 추가 (`add`)

1. 행 형식: `| <#> | 항목 | 상태 | 다음 행동 1줄 | 원천 경로 |`.
2. `#` 는 같은 접두사의 마지막 번호 + 1. 새 묶음이면 사용자에게 접두사를 묻는다.
3. 상태는 머리말의 상태 값 중 하나만 쓴다.
4. 원천은 실제로 있는 파일 경로만 쓴다. 없으면 «이 대화 YYYY-MM-DD HH:MM» 으로 적는다.
5. 자세한 내용은 원장에 쓰지 않는다. 원천 답변에 둔다.
6. 머리말의 «갱신:» 날짜를 바꾼다.

## 끝내기 (`done`)

해당 행을 «진행 중인 항목» 에서 지우고 «끝난 항목» 표에 `| # | 항목 | 끝난 날 | 원천 |` 으로 옮긴다.

## 하지 않는 것

- `MEMORY.md` 에 리마인더 줄을 더하지 않는다. 새 적용 후보는 원장 행으로만 남긴다.
- 원장 밖의 파일을 고치지 않는다.
